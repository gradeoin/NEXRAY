Stage 4 • DevOps

GitHub + CI/CD + Cloudflare (DNS/CDN/Workers)

DevOps is the part of web dev that turns code into a reliable product. You’ll learn version control, automated deployments, DNS, caching, and edge compute.

1) GitHub fundamentals (the workflow that ships)

The goal isn’t “know git commands.” The goal is: you can collaborate and recover from mistakes.

Core commands you should know

git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin <your-repo-url>
git push -u origin main

Branch workflow (safe)

git checkout -b feat/new-hero
# edit files
git add .
git commit -m "Update hero copy"
git push -u origin feat/new-hero
Pro trick: Keep main always deployable. Use feature branches + pull requests for changes.

2) CI/CD (automatic deploys)

CI = Continuous Integration (tests + checks). CD = Continuous Deployment (publish automatically). Even static sites benefit from CI: lint, link checking, build validation.

Minimal “static checks” idea

  • HTML validation (optional)
  • Link checking
  • Format consistency

Example GitHub Actions workflow (concept)

name: CI
on:
  push:
    branches: [main]
  pull_request:

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: node -v
      - run: echo "Run linters/tests here"
CI/CD is platform-specific. If you deploy with Vercel/Netlify/Cloudflare Pages, they provide “preview deploys” automatically per PR.

Secrets & environment variables

Never hardcode API keys in frontend code. Use:

  • Server-side environment variables
  • Platform secrets (Actions/Workers/Functions)
  • Public keys only on the client (if explicitly safe)
Rule: If it can be used to spend money or access private data, it must not ship in client JS.

3) Cloudflare: DNS + CDN + caching

Cloudflare sits between users and your origin server. It can speed things up and protect you.

DNS setup (typical)

  1. Buy a domain (Registrar)
  2. Set nameservers to Cloudflare (or use Cloudflare Registrar)
  3. Add DNS records pointing to your host
  4. Enable SSL/TLS (Full or Full (strict) if possible)

Caching basics

  • Static assets (CSS/JS/images) should be cacheable for a long time with fingerprinted filenames (advanced)
  • HTML is usually cached carefully (or not) so updates appear quickly
  • CDN caches at the edge near users
Pro trick: Cache aggressively for static assets; keep HTML fresh. Use cache headers intentionally.

4) Cloudflare Workers (edge backend)

Workers let you run JS/TS at the edge. Great for APIs, auth gateways, redirects, A/B tests, and caching logic.

Hello Worker (concept)

export default {
  async fetch(request, env, ctx) {
    return new Response(JSON.stringify({ ok: true }), {
      headers: { "content-type": "application/json" }
    });
  }
}

Why it’s powerful

  • Fast (edge)
  • Great for lightweight APIs
  • Can integrate with caches

Redirects (SEO + product)

A huge pro move: manage redirects properly so you don’t break links. 

/old-page  →  /new-page   (301 permanent)

301 redirects preserve SEO authority. Do not delete pages without a redirect plan.

Stage 4 assignment

  1. Create a GitHub repo and push this project
  2. Turn on preview deploys using your host (Vercel/Netlify/Cloudflare Pages)
  3. Buy a domain (optional) and connect it via DNS
  4. Write down your deployment “runbook” in a README
Runbook = the steps future‑you follows when something breaks at 2 AM.
