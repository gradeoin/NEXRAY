CSS + JavaScript + modern layout systems

1) CSS that scales (design tokens)

In real products, CSS becomes unmaintainable when everyone makes random colors, random spacing, random shadows. Fix that with tokens (CSS variables).

Example tokens (already used in this project)

:root {
  --bg: #0b0b10;
  --card: rgba(255,255,255,0.08);
  --stroke: rgba(255,255,255,0.14);
  --text: rgba(255,255,255,0.92);
  --muted: rgba(255,255,255,0.72);

  --accent: #ff5a1f;
  --accent2: #ff8a4c;

  --radius: 18px;
  --shadow: 0 12px 40px rgba(0,0,0,0.35);
  --blur: 14px;

  --space-1: 8px;
  --space-2: 12px;
  --space-3: 16px;
  --space-4: 24px;
  --space-5: 32px;
  --space-6: 44px;
}
Pro trick: If your UI looks “off”, it’s usually because you’re not consistent with spacing and type scale—not because you need a new font.

2) Layout: grid + flex (use both)

Flexbox is great for 1‑D layout (a row or a column). Grid is great for 2‑D layout (rows + columns). Modern sites use both.

Grid example

.cards {
  display: grid;
  grid-template-columns: repeat(12, 1fr);
  gap: 16px;
}

.card {
  grid-column: span 4;
}

@media (max-width: 900px) {
  .card { grid-column: span 6; }
}
@media (max-width: 600px) {
  .card { grid-column: span 12; }
}

Flex example

.row {
  display: flex;
  align-items: center;
  justify-content: space-between;
  gap: 12px;
}

Where to steal layouts (smartly)

  • layouts.dev for structure
  • designlib inspirations for vibe
  • footer.design for footers
Rule: Copy patterns, not pixels. Keep your own brand tokens (color, radius, type).

3) JavaScript fundamentals that actually matter

DOM + events

const btn = document.querySelector('[data-like]');
btn.addEventListener('click', () => {
  btn.classList.toggle('is-on');
});

This is the core interaction model: select → listen → update DOM.

Async + fetch

async function load() {
  const res = await fetch('/api/posts');
  if (!res.ok) throw new Error('Failed');
  return await res.json();
}

This is how your frontend talks to your backend (Stage 3).

The “component” mindset (no framework required)

A component is just: structure (HTML) + style (CSS) + behavior (JS) with a clear API. Frameworks help you manage components at scale—but you can learn the concept now. 

<!-- Example component: a callout -->
<div class="note">
  <strong>Heads up:</strong> This is a reusable callout.
</div>

4) Accessibility (A11y) = quality

Accessibility isn’t “extra.” It’s core product quality. It improves SEO, usability, and trust.

  • Use real buttons for actions
  • Visible focus states for keyboard users
  • Readable contrast (especially on glass)
  • Alt text for meaningful images
  • Use semantic headings (H1 → H2 → H3)

Focus state example

:focus-visible {
  outline: 3px solid rgba(255, 90, 31, 0.85);
  outline-offset: 3px;
}

Motion that doesn’t annoy people

Use subtle transitions. Respect reduced motion. 

@media (prefers-reduced-motion: reduce) {
  * { animation: none !important; transition: none !important; }
}

5) three.js animated illustration (lightweight)

This project already includes a decorative 3D scene on the homepage (#heroCanvas). Here’s how it works and how to make your own.

Where the code lives

  • js/three-scene.js: imports three.js from CDN and renders a scene
  • Canvas: <canvas id="heroCanvas"> in index.html

Minimal mental model

  • Scene: holds objects
  • Camera: viewpoint
  • Renderer: draws to canvas
  • Geometry + Material: shape + surface
  • Animation loop: updates + render per frame
Pro trick: Keep 3D “decorative” unless your product is truly 3D. It should not block the core experience.

6) Frameworks (optional, but understand why)

A framework helps when your UI becomes complex: routing, state, components, data fetching, forms, etc. But don’t use a framework to avoid learning fundamentals.

When to adopt React (or similar)

  • Many interactive components with shared state
  • Complex forms and validation
  • Large teams working on UI consistently
  • You want an app-like experience

When not to

  • Marketing site / docs / blog with minimal interactivity
  • You’re still learning HTML/CSS/JS basics

Stage 2 launch checklist

  • Layout responsive and consistent
  • Accessible focus states + headings
  • Animations respect reduced motion
  • 3D scene is optional + doesn’t tank performance
